# Video Flow

项目式视频工作台：新建项目，通过多轮对话把想法和可选图片交给本机 pi，在独立的 React + Remotion 工程里开发视频。后台持续检查、反馈和修改，通过工程验收后自动导出 MP4。工作台保存项目对话与视频版本，可以播放、跳转分镜、下载成片和源码。

## 工作台

左侧管理项目，中间持续对话，右侧查看视频和版本。页面仅使用新模板工程流程；项目列表来自 `artifacts/workspaces/`，不导入旧作品。

- 新建项目可以填写名称，也可以根据第一条想法和生成内容自动命名。
- 一个项目使用一个固定工程目录和一个持久 pi session。每次发送消息启动一轮 pi Goal，直接进入原 session，继续修改现有源码和素材；发布时另存源码与成片快照。
- 同一项目每次只执行一轮任务，任务期间可切换或新建其他项目。关闭浏览器不停止创作，重新打开可继续查看进度。
- 消息提交使用唯一编号，网络重试不会重复创建任务。文本与时间轴草稿保存在浏览器；尚未提交的图片仅保存在当前页面内存中，刷新前需要发送。
- 发布后保存对话中的版本卡片、历史成片和工程下载。查看历史版本时回到最新版本后再提交调整。
- 创作中可以取消，失败或取消后可以继续同一工程与 pi 会话。服务重启会恢复此前运行中的任务。
- 支持项目图片、可选解说时间轴和上传配音；实际交付检查和项目日志在预览区展示。

工作台的数据结构与 API 见 [工作台说明](docs/workbench.md)。

## 启动与配置

默认工程模式需要 macOS、Node.js 22.19.0+、本机 pi、FFmpeg / FFprobe。当前适配 pi 1.1.0 的 RPC 协议；Pi 要求 Node.js 22.19.0+，因此工作台和新建视频工程统一声明这个最低版本。其他系统暂未提供隔离适配器，工程模式会明确报错。

使用 nvm 时，先在本项目目录执行 `nvm install`、`nvm use`，读取 `.nvmrc` 切换版本。切换后需要停止旧服务并重新执行 `npm start`：后台进程会继续使用启动时的 Node，终端切换不会更新已运行的服务。服务启动前会检查 Node 版本，版本不符时显示实际版本和执行文件路径。

```sh
cp .env.example .env
# 编辑 .env，填入供应商的 API key
npm ci
npm start
```

```dotenv
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=你的供应商密钥
LLM_MODEL=deepseek-flash
LLM_API_STYLE=chat-completions
LLM_MAX_OUTPUT_TOKENS=48000
VIDEO_ENGINE=pi
PI_CONTEXT_WINDOW=128000
PI_INPUT_IMAGES=false
PORT=4174
```

密钥只由本地服务读取，不会进入前端、视频工程、pi 环境变量或源码压缩包。pi 通过当前工程专用的本地代理调用模型，代理令牌在任务结束后失效。使用支持 OpenAI Chat Completions 协议的供应商；支持 Responses 的供应商可改为 `responses`。可用 `PI_BIN` 指定 pi 的绝对路径，否则从 PATH 查找。

`PI_CONTEXT_WINDOW` 按供应商实际模型窗口设置；`LLM_MAX_OUTPUT_TOKENS` 是单次回答上限，应小于窗口。长视频通过文件和多轮会话完成，不需要一次返回完整 JSON。图片附件保存在独立工程中；只有确认模型支持图像输入时，才设置 `PI_INPUT_IMAGES=true`，允许 pi 读取图片及渲染帧。文本模型可以生成图形和动画，但没有模型视觉自审。

未配置密钥时，工程模式会要求配置。第一次工程创作由 Remotion 下载所需的渲染浏览器。

## 默认工程模式：pi Goal

模板 `templates/remotion-v1` 提供运行底座和能力文档，包含 React、Remotion、转场、形状、路径、文字测量和图标库。模型可以新增组件、场景、SVG、Canvas 与素材，画面造型和运动由工程源码决定。

每个项目使用 `artifacts/projects/<项目ID>/workspace/`：独立源码、素材、临时目录、HOME、pi 配置、会话和输出。原生会话始终保存到这个目录的 `control/session.jsonl`，新消息、验收反馈、取消恢复和服务重启都沿用该 session ID。空闲时可以关闭 pi 进程，下轮加载同一文件。发布后的工程快照保存在 `artifacts/projects/<项目ID>/<任务ID>/`，不随后续开发变化。依赖包固定版本并共享只读，项目无法修改依赖或其他项目；不载入用户全局扩展、技能或上下文。

后台流程：创建工程 → pi 自主开发 → 等待 `agent_settled` → 检查源码及元数据 → TypeScript / 构建 → 渲染代表帧并检查 DOM 文字边界 → 完整 H.264 导出 → FFprobe 检查尺寸、帧数与时长 → 发布作品。pi 也可以主动调用工程内的检查、抽帧和短预览工具。失败诊断返回同一会话，继续修改；有源码进展就继续运行，没有固定总轮数或总 token 预算。连续多轮验收失败且源码未变化时停止，保存现场并显示最后原因。

普通缺项由 pi 决定默认值。图片用途确实无法判断时允许提问。页面提供阶段、轮次、实时日志、取消和继续创作；浏览器关闭不停止后台任务。服务重启会自动恢复之前运行中的 pi 任务。取消不会删除工程，之后可手动继续。

通过验收后可直接播放和下载 MP4，并下载 `.tar` 源码工程。解压工程后运行 `npm ci`、`npm run render -- output.mp4` 可独立渲染；下载包不包含代理令牌、会话、依赖目录和 API key。单独运行下载的源码工程使用当前用户的普通本地权限。

### 验收和隔离边界

当前使用 macOS `sandbox-exec` 限制文件访问与网络：pi 只写自己的源码、素材与会话，通过当前任务的代理端口调用模型；渲染在另一个受限进程中执行，画面页面使用 CSP 限制同源资源。隔离策略文件保存在工程外，模型不能修改。宿主入口、依赖、模板说明、目标和验收记录由宿主维护。

这是本机进程隔离，未提供独立虚拟机、内核、CPU / 内存配额。渲染器需要访问本机回环服务，操作系统服务和只读依赖由项目共享。后续 Linux / 容器适配器需要另外实现，当前不会自动退回无权限限制的进程。

自动验收证明工程能构建和生成符合媒体规格的成片，还检查代表帧存在变化、重复渲染同一帧的结果一致。文字检查覆盖可测量的 DOM / SVG 文本边界，不覆盖 Canvas 内部文字，也不等于完整的视觉、事实或叙事质量审查。启用图像输入只表示模型具备读取帧的能力，验收记录不会据此宣称已经完成视觉审查。

工程模式支持原有可选解说时间轴、系统字幕和上传配音；工具仍未自动接入 TTS。架构、目录和 API 见 [pi Goal 架构说明](docs/pi-goal-architecture.md)。

## 旧画布 API（历史实现，工作台不使用）

2.0 使用多轮生成：整片导演设计 → 按依赖逐模块生成 → 服务端组装完整 JSON → 浏览器隔离验证与逐帧导出。最终作品大小不受单次回答长度约束，代码仍受下面的独立运行限制约束。

- 设计轮只返回小份 JSON：时间、视觉规则、主体身份与轨迹、交接状态、模块职责和函数接口。
- 代码轮每次返回一个模块的纯 JavaScript 函数体，避免在长 JSON 中转义全部代码。
- 模块按本片题材原创，共用绝对时间，可以跨镜头和同时组成图层。入口模块自行组织画面，系统不规定组件或转场。
- 输出截断或模块源码过长时，模型把当前模块拆成更小职责，父模块保留原接口。最多拆分三层、48个模块；达到限制会保存进度并显示原因。
- 模块逐个语法编译（不在 Node 中执行）、保存接口哈希和源码哈希。成功模块被复用，失败只重试当前步骤。
- 调整或绘制错误先定位模块，重新生成它及依赖它的模块；影响时长、主体身份或接口的调整重新做整片设计。旧版单体作品仍能打开，首次修改会迁移为模块作品。
- 最终用应用自己的序列化组装 `renderCode` 与作品 JSON。源代码上限为每模块48,000字符、整片768,000字符；初始化/绘制超时和隔离权限保持原规则。多轮生成不保证任意规模程序都能运行。

### 模块接口

模块源码是 `(env, deps)` 工厂函数的函数体。`env` 提供 `ctx,t,width,height,assets,utils,design`，`deps[模块ID]` 提供依赖模块的函数接口。每帧按依赖顺序重新创建模块，模块返回同步函数对象，入口导出 `render()`。调用异常会标记模块ID，供局部修复定位。设计中的交接时刻会增加前后画面采样；采样可绘制仍不等于视觉衔接正确。

### 生成任务与恢复

页面“创作进度”显示后台任务与已完成部分。刷新后通过浏览器保存的任务ID重新连接当前任务；服务重启将运行中任务标为中断，可以选择“继续创作”。任务输入、设计、模块与模型用量逐步原子写入 `artifacts/jobs/<jobId>.json`。修改任务恢复时检查作品版本，防止旧任务覆盖新作品。

API：`POST /api/plan` 传 `async:true` 返回202与jobId；`GET /api/jobs/<id>` 返回状态或完成结果；`POST /api/jobs/<id>/resume` 继续任务；`GET /api/jobs` 列出未完成任务。未传async时保持等待完整结果的调用方式。生成与恢复不因浏览器断开而取消。

`LLM_MAX_OUTPUT_TOKENS` 是每次模型调用预算，包含供应商计入的推理；不再固定截到48,000，可设置供应商接受的值。可选 `LLM_REASONING_EFFORT` 直接传给供应商，默认不传；可选 `LLM_REQUEST_TIMEOUT_MS` 默认300,000毫秒。模块拆分仍需要每轮有足够的可见输出空间。

旧版把模型输出限制为固定图形类型、布局和动画。1.0 改为让模型为**整条视频编写独立 Canvas 绘制程序**：

- 造型：原生路径、曲线、字形、渐变、纹理、图像合成、辅助画布与伪三维投影。
- 动作：直接用绝对时间 `t` 计算画面，可自行写关键帧、形变、镜头和衔接。
- 构图与文字：完全由程序决定；系统不叠加标题、正文、水印或统一转场。
- 时间说明：`scenes` 仅用于界面时间线，不能决定画面组件。
- 素材：`assets` 是附件解码后的 ImageBitmap；模型自行决定内容素材、风格参考或不用。用途无法判断时提问，其余缺项由模型决定。

模型返回 `renderCode` 函数体，调用接口：

```js
render(ctx, t, width, height, assets, utils)
```

`utils` 提供 `duration`、`clamp`、`lerp`、`smooth`、`easeOut` 与 `random(seed)` 等数学函数。没有图形或动画预设库。兼容模型返回完整 `function render(...) { ... }` 或返回绘制函数的形式；执行入口会写入日志。每帧都从空白开始，必须能直接绘制任意时间；随机数应采用固定种子。

当前运行环境支持 3–1800 秒；宽高比由两个正整数指定，范围 0.4–2.5，例如 16:9、9:16、1:1、21:9。默认短片短边720px，超过两分钟的长片短边1080px，长边取偶数。支持最多120个片段的长片、解说时间轴、同步字幕和配音。

## 执行、验证与导出

- 绘制程序在没有同源权限的沙箱 iframe 中，由独立 Blob Worker 执行。CSP 禁止网络；Worker 没有 DOM；程序不会在 Node 或主页面执行。源码检查额外拒绝非绘图能力，**源码检查本身不是安全边界**。
- 初始化和绘制有超时，超时终止 Worker，防止无限计算卡住主界面。
- 预览通过 ImageBitmap 回传主画布。可以播放，也可以拖动时间线或点击时间说明跳转。
- 执行校验包括镜头边界、每半秒采样、透明空白、时间变化、任意跳转后的确定性和计算耗时。采样或完整逐帧导出中出现的绘制错误会送回模型修复，单阶段最多两轮；修复失败直接显示原因，不替换为固定模板。
- 校验通过只说明程序可运行，不等于视觉效果、叙事或循环衔接都符合预期。循环首尾差异会显示提示。
- 优先使用 WebCodecs，将 `i / 30` 秒的每一帧按精确时间戳编码为 H.264，FFmpeg 封装 MP4。帧数为 `round(duration × 30)`。不支持 H.264 WebCodecs 的浏览器回退到实时 WebM 录制再转码，该路径可能掉帧。
- 导出后用 FFprobe 检查编码、尺寸、帧率、时长和逐帧路径的帧数。页面展示实际 MP4，可播放和下载。

## 保存与恢复

每次 AI 创作的描述、附件、导演设计、模块源码、完整程序和分轮模型用量记录在 `artifacts/generations/<id>.json`，导出视频保存为同编号 `.mp4`。刷新后可以用“已保存作品”恢复，不需要重新调用模型。可以在“调整这条作品”中提交具体画面或动作反馈。修复和调整会保存旧程序到记录的 revisions，并把已有旧视频备份至 artifacts/revisions；页面展示最新版本。

旧版源码保存在 `artifacts/legacy-v05`，便于对照与恢复。

## 能力范围

这是由语言模型编程创作的动态图形、插画、字体与素材动画系统。自由创作空间来自源码；作品水平仍取决于模型的造型和动画能力。它没有接入扩散视频模型。默认无配音，上传音频后可合成音轨；工程自身也可以使用本地音频素材。

基础契约检查：`node scripts/verify-contract.mjs`。本轮成片与浏览器验证记录见 `artifacts/review/README.md`。

## 运行日志

对话区顶部「pi 执行历史」直接展示项目原生 session 中保存的消息、思考记录、工具参数与结果、验收反馈和上下文整理。已有记录支持分页回看，刷新后保留，并可下载完整执行历史；实时更新只读取新追加的记录。向上浏览暂停跟随，点击「跟随最新」回到末尾。

右侧「项目运行日志」通过 SSE 展示宿主、模型响应、工具执行、验收、渲染和错误。终端同步输出结构化事件，持久化至 `artifacts/logs/YYYY-MM-DD.jsonl`（按北京时间分日）。每轮操作有 `runId`，每次服务请求有 `requestId`，通过 `generationId` 关联项目。项目日志跨日期读取，支持加载更早记录和下载全部项目日志。

后台多轮阶段用 `jobId`、`generationId`、`runId` 关联，记录 design/module/split/assemble、模块进度、接口复用、每轮用量与恢复原因。

```sh
tail -f artifacts/logs/$(TZ=Asia/Shanghai date +%F).jsonl
```

日志只记录阶段、耗时、用量、长度、进度和错误诊断，不记录请求正文、图片数据或完整程序；已配置 API key 会被脱敏。完整程序仍保存在作品 JSON 中。日志从这一版本开始产生，之前的过程日志无法补回。

## 长视频解说

在「长视频解说与字幕」中导入 JSON 时间轴后，总时长与片段顺序由应用锁定。模型决定画面和动作，读取 `env.design.storyboard.scenes` 中的 `startSec/endSec/headline/body/visual/chapter/source`。系统在主画布叠加字幕，画面需保留底部15%安全区。

时间轴格式：`{title, researchedAt, scenes:[{id,durationSec,headline,body,narration,visual,chapter,source,cues:[{startSec,endSec,text}]}]}`；字幕时间相对所在片段。默认可以只写想法，时间轴是可选输入。

生成画面后可上传配音（最大200 MB）；需要与视频总时长一致，允许0.5秒误差。服务使用FFprobe检查音频流与时长，再转成AAC，导出时同步封装。配音按作品与时间轴关联，时间轴变更后旧配音不会自动复用。预览支持音频同步播放。工具不自动调用云TTS；本次Agent介绍视频使用本机macOS Tingting生成旁白。

长片H.264编码按约2 MB转存Blob，避免长期保留所有帧的JS字节数组；服务端按流写入文件，视频播放使用范围流，前端导出只收到元数据与已保存视频链接。仍需足够本地磁盘空间，浏览器不支持WebCodecs时采用实时录制。

示例成片材料位于 `artifacts/agent-explainer/`，含研究来源、解说稿、时间轴和字幕。
